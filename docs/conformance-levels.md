# プロジェクトの適合レベル定義

レベルの意味と、特定仕様版・実装が対応しているレベルは区別する。

各レベルは独立して扱う。数字の大きいレベルのテスト通過は、数字の小さいレベルのすべてへの適合を保証しない。
複数レベルの適合を主張する場合はそれぞれの実行結果を示す。共通入力処理の実施は他レベルの適合保証ではない。

| レベル | 検証対象 |
|---|---|
| L0 | ファイル形式、Manifest、Markdown構文 |
| L1 | 法令の階層、番号、項・号の意味構造 |
| L2 | 法令内の明示的参照とファイル間参照 |
| L3 | 原典との内容一致、改正履歴、施行時点 |
| L4 | 他法令との参照整合性 |

## v1alpha1との照合

validatorは仕様commit `b704631b6501a0a01c1eb6faf99cfe16a4bccfa9`を固定参照し、
正式ランナーはcase.levelごとに検証する。

VAL-01はL0をManifest・ファイル/encoding・CommonMark構文解析、L1を構造・番号・表示・ID・ASTとする。
MD-03はCommonMarkが任意テキストを解析できることを明記し、Markdownとしての構文と法令固有構造の違反を区別する。
validatorのL0はCommonMarkパーサーを実行するが、法令固有の構文・意味検査はL1で実行する。
「Markdown構文」を単なる読込と言い換えない一方、未閉鎖フェンス等をCommonMark違反と自動的に扱わない。
Markdown一般構文、法令用追加構文、意味制約のレベル配分は、規範とケースを対応させて判断する必要がある。

現行v1alpha1の正式対応はL0/L1のみ。L2の予約設計は同法令の論理参照を扱うが、プロジェクトのL2定義を
そのリンク方式だけに狭めない。L3の施行時点とL4の他法令参照を省略した略称は定義として使わない。
ファイルを統合して意味ASTを作る処理と、ファイル間参照の解決・整合性検査も区別する。

固定適合テストの成功は、全検証対象の網羅性の証明ではない。

## 既定の次期仕様との照合

次期仕様は `8f6a357007289271c115e60a9b0845fb14f52134` に固定しています。
L0はファイル・Manifest、L1はMarkdown固有構造・番号・表示・ASTです。MD系列の違反はL1で扱います。
L3はRecordごとの `historyStructure` と `evidence`、L4はRecordごとの
`relationResolution`・`relationConsistency`・`timeConsistency`・`displayConsistency`を独立して報告します。
L2・L3/sourceMatch・L4/clauseReferenceは予約済みで、実装済みとは主張しません。
登録台帳・再構築報告・変更・固定参照解決はレベル外の独立した検査です。

違反はfail、違反がなく処理不能または判定不能ならincomplete、対象がなければnotApplicableです。
警告・保留だけならpassになります。HIST-06/12の警告専用検査の判定不能は集計から除きます。
結果の対象をcommitに固定できないディレクトリ入力は、特定の記録版への適合の主張には使えません。
規範適合ケース463件の成功は必要条件であり、未知の入力に対する完全性や法的正確性を保証しません。
