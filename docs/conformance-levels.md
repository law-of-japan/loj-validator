# プロジェクトの適合レベル定義

2026-11-07、ユーザーがこのCodexセッションで明示した定義。今後の設計・レビュー・引き継ぎの基準とする。
レベルの意味と、特定仕様版・実装が対応しているレベルは区別する。

各レベルは独立して扱う。数字の大きいレベルのテスト通過は、数字の小さいレベルのすべてへの適合を保証しない。
複数レベルの適合を主張する場合はそれぞれの実行結果を示す。共通入力処理の実施は他レベルの適合保証ではない。

| レベル | 検証対象 |
|---|---|
| L0 | ファイル形式、Manifest、Markdown構文 |
| L1 | 法令の階層、番号、項・号の意味構造 |
| L2 | 法令内の明示的参照とファイル間参照 |
| L3 | 原典との内容一致、改正履歴、施行時点 |
| L4 | 他法令との参照整合性 |

## 現行仕様・実装との照合

仕様側のVAL-01/CONF-02をこの独立性に合わせて訂正した。現行validatorの固定commit6295fd7は訂正前なので、
その累積適合の文言は今回のユーザー指示で撤回された旧記述として扱う。固定参照の更新は仕様訂正の統合時に行う。
正式ランナーは既にcase.levelごとに実行しており、L0ケースのL1継承テストを追加する必要はない。
CONF-01のL0正例契約はIssue #1で解決するため保留し、今回の作業・merge判断の阻害事項とはしない。

固定仕様6295fd7のVAL-01はL0をManifest・ファイル/encoding・独立Markdown読込、L1を構造・番号・表示・ID・ASTとする。
MD-03はCommonMarkが任意テキストを解析できることを明記し、Markdownとしての構文と法令固有構造の違反を区別する。
validatorのL0はCommonMarkパーサーを実行するが、法令固有の構文・意味検査はL1で実行する。
「Markdown構文」を単なる読込と言い換えない一方、未閉鎖フェンス等をCommonMark違反と自動的に扱わない。
Markdown一般構文、法令用追加構文、意味制約のレベル配分は、規範とケースを対応させて判断する必要がある。

現行v1alpha1の正式対応はL0/L1のみ。L2の予約設計は同法令の論理参照を扱うが、プロジェクトのL2定義を
そのリンク方式だけに狭めない。L3の施行時点とL4の他法令参照を省略した略称は定義として使わない。
ファイルを統合して意味ASTを作る処理と、ファイル間参照の解決・整合性検査も区別する。

正式104ケース成功と既存CI成功は固定仕様に対する結果であり、この定義に基づく全検証対象の網羅性の証明ではない。
本記録は仕様・スキーマ・ケース・コードを変更するものではない。
