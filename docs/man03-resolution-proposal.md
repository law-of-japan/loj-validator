# MAN-03附属資料分割：仕様判断記録（B案採用）

2026-11-06 JST。[loj-spec #2](https://github.com/law-of-japan/loj-spec/issues/2)の検討資料。
ユーザーがB案を承認した。採用規範はloj-spec `6295fd7769a09eeb0da56bcc6ff8c404ec391db6` のMAN-03。
本書の選択肢は検討履歴であり、規範は仕様リポジトリを参照する。

## 根拠と判断対象

固定commit b2356c6のMAN-03は独立したCommonMark文書、完結ブロック間の分割、後続ファイルの
条/分類見出し開始を規定する。一方HEAD-03は附属資料の本文と追加見出しを不透明に扱い、
MD-03は未閉鎖フェンスがCommonMarkではEOFまでコードとなることを明記する。
両EBNFに分割完結の定義はなく、T052は単一ファイルなので判断材料が不足する。

決めるべき点は、(1)見出し開始条件の附属資料への適用、(2)非最終ファイルのEOFによる
暗黙終端の許容範囲、(3)元ファイルの独立解釈と単純連結表示の関係である。

CommonMark側の終端条件は公式[フェンス規則](https://spec.commonmark.org/0.31.2/#fenced-code-blocks)と
[HTMLブロック規則](https://spec.commonmark.org/0.31.2/#html-blocks)を確認した。
EOFや囲むブロックの終端も通常の終了条件となるため、案Bは明示的な追加制約として規定する必要がある。

## 選択肢

| 案 | 規範として明確化する内容 | 利点・影響 |
|---|---|---|
| A | 附属資料の後続ファイルは任意のMarkdownブロックで開始できる。各ファイルのEOF終端も完結と認める | CommonMarkの独立文書規則に単純に従えるが、誤って途中分割したフェンスを検出できない |
| B（採用） | 見出し開始条件は本則・条形式附則に限定。附属資料は任意の本文ブロックで開始可能。非最終ファイルの明示終端を要するブロックは閉じてから分割する | 偶発的なコード/HTMLの途中分割を防ぐ。CommonMark追加制約として閉鎖条件の具体的定義が必要 |
| C | v1alpha1の附属資料を単一ファイルに限定 | 実装は簡単だが既存MAN-03の分割許可を狭める仕様変更になる |

## 承認時に提示したB案の具体化（検討履歴）

- 後続附属資料ファイルは区切り空行を除き非空の本文で開始できる。条や分類の意味見出しを要求しない。
  追加見出しはHEAD-03どおり本文。予約マーカーの禁止は現状を維持する。
- 非最終ファイルのフェンスは、CommonMarkの文字種・長さ・インデント条件に合う明示閉じフェンスを必要とする。
- HTMLブロックも種類別に定義する。終了文字列を持つ種類1〜5はその終了文字列、
  空行で終わる種類6〜7は空行を非最終ファイル内に置く案とする。コード/引用/リスト内の文字列を
  独立したHTML開始と取り違えない。段落等の通常EOF終端を一律禁止しない。
- 最終ファイルのEOF終端はMD-03のCommonMark規則を維持する案とする。
- ファイル独立性と原文・意味AST/IDの安定性を保証対象とし、無区切り連結したHTML表示の同一性は保証しない。
  ファイル移動時にリンク参照定義のスコープを変えないことも明示する。

上記は採用前の提案。ユーザー承認後、引用・リスト内の実ブロックにも明示終端条件を適用することをMAN-03で確定した。
本書の旧提案と詳細が異なる場合は、固定spec commitの規範文を優先する。

## 仕様側で独立に整備した検証例

通常段落・リスト・引用・追加見出しでの適法分割、空白だけの後続ファイル、明示閉鎖/未閉鎖フェンス、
バックチック/チルダと閉じ長さ違い、各HTMLブロック種類、最終ファイルEOF、参照定義のファイル分離。
正例ASTは手定義し、負例はMAN-03と該当ファイル/開始位置を規範で決める。
既存74ケースの期待値をvalidator出力で更新しない。

## 採用前の保留方針の再レビュー（履歴）

全複数ファイル附属資料をL1 Incompleteにする範囲は保守的で、閉じたフェンスや通常段落も含む。
個々の合法性を未決のまま選別しないため、初期実装の制限として維持する。
L0はManifest・ファイル・encodingの検査でありこのL1保留を適用しない。単一ファイルは影響を受けない。
状態の優先順位はError > Incomplete > Failed > Passed。既知違反が保留と同時に存在すれば
Incompleteでも違反診断を保持し、IO不能が併存すればErrorとなる。どちらも完全ASTを返さない。

解除条件は、仕様判断の明示承認、loj-spec側の規範・独立期待値整備、固定commitの計画的更新、
validator側の実装と全適合再検証である。Issueが作成済みというだけでは解除しない。
